Documentación de la API v2.2.0

📘 Introducción

Qué es la API y cómo está organizada.

La API Colección de Videojuegos es un servicio REST que expone todos los datos de una ludoteca: un catálogo compartido de videojuegos, plataformas, géneros y desarrolladoras, y la colección personal de cada usuario (sus ejemplares, con estado, precio de compra, valoración y favoritos).

Todo se comunica en JSON sobre HTTP, usa los verbos estándar (GET, POST, PUT, PATCH, DELETE) y sigue unos códigos de estado convencionales.

Base URL

http://localhost:8000

Si sirves la API en otro host o puerto, sustitúyelo. Todas las rutas de esta documentación son relativas a esa base (por ejemplo, /api/videojuegos → http://localhost:8000/api/videojuegos).

Apartados de la API

🔐 AutenticaciónRegistro, login, refresco de token y cambio de contraseña.
🕹️ VideojuegosEl catálogo: CRUD con carátula, filtros y paginación.
💾 PlataformasConsolas y sistemas donde salen los juegos.
🎭 GénerosRPG, acción, aventura… etiquetas del catálogo.
🏢 DesarrolladorasEstudios y editoras, con país y web.
📚 ColecciónTus ejemplares: estado, precio, valoración y favoritos.
📊 EstadísticasResúmenes y conteos de tu colección.
👥 UsuariosCuentas de la plataforma: roles y administración.

🔐 Autenticación (JWT)

Todos los endpoints la requieren salvo el registro, el login, el refresco, la raíz /, /api/salud y /api/estadisticas/por-genero.

La API usa tokens JWT firmados con HMAC SHA-256 en el esquema Bearer. Al registrarte o iniciar sesión recibes dos tokens:

  • Access token — corto, dura 8 horas (28 800 segundos). Es el que envías en cada petición.
  • Refresh token — largo, dura 7 días (604 800 segundos). Solo sirve para renovar la sesión en POST /api/auth/refresh sin volver a introducir la contraseña.

Cómo enviar el token

Añade la cabecera Authorization con el valor Bearer seguido del access token:

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6... Content-Type: application/json

Renovar la sesión (refresh)

Cuando el access token caduca (respondrá 401), envía el refresh token a POST /api/auth/refresh. Devuelve un par nuevo de tokens y el refresh anterior deja de servir (rotación): guarda siempre el último par que recibas.

Seguridad adicional

  • Las contraseñas se guardan con bcrypt, nunca en claro.
  • Cada cuenta tiene una versión de token: al cambiar la contraseña, todos los tokens emitidos hasta ese momento quedan anulados y las demás sesiones abiertas mueren.
  • POST /api/auth/cambiar-password exige la contraseña actual: un token robado no basta para quedarte en una cuenta.
  • Cambia la secreta en producción con la variable de entorno LUDOTECA_SECRET_KEY.

🛡️ Roles y permisos

Cada cuenta tiene un rol que decide qué puede hacer.

RolPuedeNo puede
usuario Consultar el catálogo y gestionar su propia colección y su contraseña. Modificar el catálogo ni ver otras cuentas.
gestor Todo lo anterior más editar el catálogo (videojuegos, plataformas, géneros y desarrolladoras) y consultar las cuentas de usuarios. Asignar roles, restablecer contraseñas ajenas o eliminar cuentas.
admin Todo lo anterior más asignar roles, restablecer contraseñas y eliminar cuentas (con su colección, en cascada). Cambiarse el propio rol o eliminarse a sí mismo (siempre debe quedar al menos un administrador).
⚠️ Si un endpoint exige un rol superior al tuyo, la API responde 403 Forbidden con un mensaje explicando el permiso necesario.

🚀 Primeros pasos

De cero a tu primera petición autenticada, con curl.

1. Regístrate (o inicia sesión)

# Registro — crea la cuenta y devuelve los tokens (HTTP 201) curl -X POST http://localhost:8000/api/auth/registro \ -H "Content-Type: application/json" \ -d '{"nombre": "Maic", "email": "maic@ejemplo.com", "password": "secreto123"}' # Login — mismo resultado si la cuenta ya existe (HTTP 200) curl -X POST http://localhost:8000/api/auth/login \ -H "Content-Type: application/json" \ -d '{"email": "maic@ejemplo.com", "password": "secreto123"}'

La respuesta trae el par de tokens y los datos de la cuenta:

{ "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6...", "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6...", "token_type": "bearer", "expira_en_segundos": 28800, "refresh_expira_en_segundos": 604800, "usuario": { "id": 1, "nombre": "Maic", "email": "maic@ejemplo.com", "rol": "usuario", "activo": true } }

2. Usa el token en cada petición

curl http://localhost:8000/api/videojuegos \ -H "Authorization: Bearer TU_ACCESS_TOKEN"

3. Renueva la sesión cuando caduque

curl -X POST http://localhost:8000/api/auth/refresh \ -H "Content-Type: application/json" \ -d '{"refresh_token": "TU_REFRESH_TOKEN"}'
🧪 ¿Prefieres probar a mano? El Swagger (arriba) tiene un botón Authorize: pega ahí tu access token y todos los endpoints quedan desbloqueados. También hay una colección de Postman en APPWEB_AUTH/postman_collection.json.

📄 Paginación y filtros

Los listados grandes devuelven páginas, no listas enteras.

Tres endpoints devuelven resultados paginados: GET /api/videojuegos, GET /api/colecciones y GET /api/usuarios. Aceptan los parámetros de consulta:

ParámetroPor defectoDescripción
pagina1Número de página (mínimo 1).
por_pagina20Resultados por página (de 1 a 100).
q—Texto de búsqueda (título/descripción, o nombre/email en usuarios).

Toda respuesta paginada tiene esta forma:

{ "total": 57, // resultados que cumplen el filtro "pagina": 2, // página actual "por_pagina": 20, // tamaño de página "paginas": 3, // total de páginas "items": [ ... ] // los elementos de esta página }

Filtros y ordenación

Cada listado tiene además sus propios filtros, recogidos en la página de endpoints. Por ejemplo:

# Catálogo: juegos de RPG de Switch ordenados por año GET /api/videojuegos?genero=RPG&plataforma=Nintendo%20Switch&orden=anio-desc # Mi colección: solo favoritos con valoración mínima de 8 GET /api/colecciones?favorito=true&valoracion_min=8 # Usuarios: búsqueda por texto y filtro de rol (gestor o admin) GET /api/usuarios?q=maic&rol=usuario
🔎 Los filtros de género, plataforma y desarrolladora del catálogo aceptan ID o nombre: ?genero=3 y ?genero=RPG son equivalentes.

🚨 Códigos de estado

Así responde la API ante cada situación.

CódigoSignificadoEjemplo
200 OKPetición correcta (GET, PUT, PATCH, DELETE).Listar videojuegos.
201 CreatedRecurso creado con éxito.Registro o alta de un juego.
400 Bad RequestDatos incorrectos (validación o lógica).Contraseña actual errónea al cambiarla.
401 UnauthorizedFalta, caducó o no es válido el token.Acceder sin cabecera Authorization.
403 ForbiddenToken válido, pero tu rol no alcanza.Un «usuario» intentando crear un juego.
404 Not FoundEl recurso pedido no existe.GET /api/videojuegos/999999.
409 ConflictLa operación entraría en conflicto.Email ya registrado, duplicado en la colección, borrar lo que está en uso.

Todos los errores tienen el mismo formato, con un mensaje legible en detail:

{ "detail": "El videojuego con id 999999 no existe" }

🌍 Ejemplos con fetch (JavaScript)

Listo para pegar en la consola del navegador o en tu frontend.

Iniciar sesión

const BASE = "http://localhost:8000"; const res = await fetch(`${BASE}/api/auth/login`, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ email: "maic@ejemplo.com", password: "secreto123" }), }); const { access_token, refresh_token } = await res.json();

Listar videojuegos con un filtro

const res = await fetch( `${BASE}/api/videojuegos?q=zelda&orden=anio-desc&por_pagina=5`, { headers: { Authorization: `Bearer ${access_token}` } } ); const { total, items } = await res.json();

Añadir un juego a mi colección

await fetch(`${BASE}/api/colecciones`, { method: "POST", headers: { "Content-Type": "application/json", Authorization: `Bearer ${access_token}`, }, body: JSON.stringify({ videojuego_id: 1, plataforma_id: 2, estado: "bueno", precio_compra: 59.99, valoracion: 9, favorito: true, }), });

Renovar la sesión al recibir un 401

const nueva = await fetch(`${BASE}/api/auth/refresh`, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ refresh_token }), }); const par = await nueva.json(); // par.access_token y par.refresh_token sustituyen a los anteriores
